1. 파이프라인 개요

1.2 Reconstruction reconstruction/modules/

엔트리포인트는 v2d_pipelines/run_ego_reconstruction.py --hand_tracking hamer이고, 이것이 run_ego_wilor.py로 디스패치한다. 각 단계는 v2d_docker/container.py의 run_in_container()로 해당 이미지를 띄우며, 출력이 이미 존재하면 _step()이 건너뛴다(캐시). 단계 시간은 v2d_common/stage_timing.py가 stage·container 2계층으로 기록한다. 아래는 실행 순서다.

  1. AnyCalib undistortion v2d_anycalib
    렌즈 왜곡 제거와 초기 intrinsics 추정. 이후 모든 단계는 anycalib/undistorted.mp4를 입력으로 쓴다.
  2. Extract frames host
    PNG 프레임 추출 → frames/
  3. MoGe depth + intrinsics v2d_moge
    단안 metric 깊이. 논문이 말하는 파이프라인의 metric 앵커다 — 물체 크기, 손 스케일·이동, 카메라 궤적이 모두 이 깊이에 맞춰진다.
  4. Stabilise intrinsics host
    프레임별 intrinsics를 하나로 안정화 → intrinsics_stable.json
  5. DROID-SLAM trajectory v2d_droid_slam
    카메라 궤적(camera_to_world). MoGe 깊이에 스케일 정렬되며, gsplat 정제의 배경 pose field 초기값으로도 쓰인다.
  6. WiLoR per-frame detection + MANO v2d_wilor
    손 검출과 마스크. 이 경로에서는 SAM2의 손 프롬프트 소스(sam2_hand_prompt_source: wilor_mask)로만 쓰이고, 최종 손 포즈는 HaMeR이 낸다.
  7. Grounding DINO (ref frame) v2d_grounding_dino
    기준 프레임에서 텍스트 프롬프트 "a tissue box"로 물체 박스 검출.
  8. SAM2 mask propagation v2d_sam2
    물체(track 1)와 양손(track 2, 3) 마스크를 전체 영상으로 전파 → masks/{1,2,3}/
  9. SAM3D mesh generation v2d_sam3d
    기준 프레임에서 텍스처 메시 생성. 스케일은 미정(up to scale). 첫 시도는 libusb 문제로 실패해 이미지를 재빌드했다(timing_tissue_box_failed_sam3d/).
  10. FoundationPose scale estimation v2d_foundation_pose
    SAM3D 메시를 MoGe 깊이에 등록해 metric 크기 추정 → mesh_scaled.obj, scale.json
  11. FoundationPose tracking v2d_foundation_pose
    6-DoF 물체 포즈 추적 → poses/
  12. EKF pose smoothing host
    물체 포즈 시간축 평활화 → poses_smoothed/
  13. HaMeR per-frame regression v2d_hamer
    SAM2 손 마스크를 크롭해 MANO 파라미터(betas, finger pose, global orient) 회귀. 오른손 전용 모델이라 왼손은 이미지를 좌우 반전해 추론하고 결과를 다시 미러링한다. 그래서 재구성에는 MANO_RIGHT.pkl만 필요하다.
  14. Align HaMeR hands to depth v2d_hamer
    렌더한 손을 시선 방향으로 이동시켜 MoGe 깊이와 맞추고, 프레임별 이동과 전역 손 스케일(hand_*_scale)을 복원. 이 값이 1.47 / 1.52로 나온 것이 이후 모든 스케일 문제의 출발점이다.
  15. Interpolate HaMeR aligned frames host
    누락 프레임 보간 → hamer_aligned_filled/
  16. Simple 2DGS refinement v2d_gsplat_refinement
    물체·손 메시에 앵커된 가우시안 + 깊이 초기화 배경으로 L1 photometric 손실을 최소화. 물체 pose/scale, 손 root/articulation/shape/scale, 카메라 pose를 공동 최적화. 두 번째 실행에서 추가됐다. → poses_refined_simple/, hamer_refined_simple/, camera_refined_simple/, refined_object_scale.json
  17. GeoCalib intrinsics + gravity v2d_geocalib
    중력 방향 추정 → geocalib/gravity.json
  18. Package result/ host
    write_result_bundle()이 _first_populated_dir()로 가장 정제된 포즈·손 디렉터리를 골라 result.npz(23~27 키), mesh.obj, manifest.json으로 묶는다. result/가 이미 있으면 건너뛰므로 정제 후에는 기존 디렉터리를 옮겨야 재패키징된다.
  19. Gravity-align result_slam_gravity_aligned/ host
    GeoCalib 중력을 -Z로 회전한 별도 번들. 4개의 gravity 키가 추가되며, 이것이 레벨러의 입력이 된다.
  20. Export Three.js result scene host
    브라우저 뷰어 → threejs_scene/

1.3 Bundle 보정 호스트 / rg-retarget 컨테이너

재구성이 낸 번들은 그대로 로더에 넣을 수 없었다. 두 가지 보정을 순서대로 적용했다.

  1. Metric 재스케일 reconstruction/scripts/scale_result_bundle.py
    손 스케일 평균 1.4463의 역수 0.6914를 모든 길이(camera/object/wrist translation, mesh 정점, hand_*_scale)에 곱한다. object_to_camera 회전 블록에 섞인 similarity scale을 분리(_rigidify_similarity)한 뒤 world transform을 재합성한다. 처음에는 같은 기능을 rescale_result_bundle.py로 중복 구현했다가 기존 도구를 발견해 삭제했다.
  2. 중력 레벨링 v2d_task_library_loader/lib/level_result_bundle.py
    메시의 bbox-부피 최소화 정규 축을 찾고(2° 격자 × 0.25° 정밀 탐색, 34k 정점, 약 4분), 선택한 축(--up_rank 1, 중간 축)을 frame-0에서 +Z로 보내는 회전을 모든 *_to_world에 적용. 보정각 7.01°. 접촉 footprint 14.9×4.1 cm(모서리) → 20.3×10.3 cm(면). 축 세 개를 비교하는 보조 스크립트 compare_up_ranks.py를 out/timing/에 두어 정규 탐색을 한 번만 돌렸다.

1.4 Robotic grounding robotic_grounding/ · 컨테이너 robotic-grounding:latest (Isaac Lab 2.3.2)

컨테이너는 --gpus device=6,7 --entrypoint /bin/sleep로 띄웠다. 이미지는 GPL 격리 정책상 manotorch를 빼고 빌드되므로 로더 실행을 위해 manotorch, chumpy(--no-build-isolation), v2d_common, v2d_task_library_loader를 editable로 설치했다. 데이터셋 등록은 retarget/dataset_registry.py의 ego_recon 항목이 담당하며, 로더 산출물은 gitignore된 .cache/ego_recon/loaded/에, 나머지 에셋은 assets/human_motion_data/ego_recon/processed/에 놓인다.

  1. Loader v2d_task_library_loader/lib/ego_recon_loader.py
    result.npz의 MANO 파라미터를 read_mano.py(manotorch, 양손 레이어를 무조건 생성 → MANO_LEFT.pkl 필수)로 FK하여 21 관절 위치·접촉 라벨을 만들고 loaded Parquet으로 저장. --ground_z_offset 1.0(테이블 높이), --no_ground_align(이미 레벨링됨). 물체 메시를 <seq>.obj로 설치하며 이름 재사용 시 서명 불일치로 거부한다. world-repose 게이트 1.1e-7 / 1.2e-7 m.
  2. IK 리타게팅 scripts/retarget/ego_recon_to_sharpa.py
    pinocchio 기반 differential IK. 손목 pose와 fingertip residual을 추종하며 관절 한계를 지킨다. --mano_to_robot_scale 1.2(손 스케일 ≈1.0 전제). 번들이 metric이므로 --surface_project류 보정은 쓰지 않았다. 출력은 motion_v1 스키마 Parquet(62 컬럼: robot_*_frames, *_task_errors, 접촉 등).
  3. Rigid URDF scripts/generate_rigid_urdfs.py --dataset ego_recon
    메시에서 충돌 STL(<seq>_visual.stl)과 <seq>_rigid.urdf 생성.
  4. Support surface scripts/reconstruct_support_surfaces.py
    물체가 정지한 프레임(238개, 7 세그먼트)에서 접촉 디스크를 추정·병합 → reconstructed_stage/<seq>_support.usda. "kept 1 above ground"가 통과 조건이다.
  5. 운동학적 검증 영상 scripts/retarget/vis_retargeted.py --save_mp4
    viser로 리타게팅 결과를 재생한 MP4. 물리 없음 — 박스는 지정된 자리에 그려질 뿐이다. → out/tissue_box_refined.mp4
  6. PPO 학습 scripts/rsl_rl/train.py --task Sharpa-V2D-v0
    rsl_rl PPO, Hydra 오버라이드. 환경 정의 tasks/v2d/v2d_hand_env_cfg.py, 커리큘럼 tasks/v2d/mdp/curriculum.py(FixedTimestepCurriculum: VOC 스케일과 보상 가중치를 iteration 스케줄로 갱신), 종료 조건 tasks/v2d/mdp/terminations.py. 에이전트 설정 config/sharpa_wave/agents/rsl_rl_ppo_cfg.py(num_steps_per_env 24, save_interval 200). 해석된 전체 설정은 logs/.../params/env.yaml에 저장된다.
  7. 평가·렌더 scripts/rsl_rl/eval.py --task Sharpa-V2D-v0-Play --video
    체크포인트를 로드해 1 env 롤아웃을 400 스텝 녹화. 물리 있음 — 이 영상만이 정책의 실제 행동이다. → logs/.../videos/play/rl-video-step-0.mp4

hand_*_scale은 아무도 읽지 않는다. 로더와 리타게터 어디에도 소비 코드가 없다. 단안 SLAM은 스케일을 정하지 못하고 손 피팅이 잔차를 흡수하는데, 하류가 손을 MANO 템플릿 크기로 만들면서 월드는 재구성 스케일 그대로 쓰니 손이 물체 대비 1.45배 작아진다. 번들 전체를 1/1.4463배 하면 손과 무관한 물체 치수가 20.3 × 11.1 × 10.5 cm로 실물에 근접해, 진단과 보정 계수가 교차검증된다.

gsplat 정제는 스케일을 잡지 못했다. 손 스케일이 3%, 물체 메시가 7.5%(refined_object_scale 0.9252) 움직였을 뿐이다. --w_hand_scale_prior 10.0이 학습된 스케일을 깊이 정렬 추정치에 강하게 묶어두기 때문이며, 논문의 "공동 최적화" 서술과 구현의 자유도가 다르다. 정제의 실질 효과는 다음 절의 관통 감소였다.

2.4 학습 설정

레시피 — README "Ego-video (monocular) sequences"의 force-closure 레시피. 단안 접촉 기하가 노이지해 contact_wrench_support_reward 대신 force_closure(5.0)를 쓰고, 접촉 항 3개를 env.rewards.*.weight와 커리큘럼 params.rewards_* 두 곳 모두 0으로 둔다.

예산 — 4096 env, --video 없음. 실측 7.019 s/iter(n=29), 기동 153 s → 8시간 = 4079 iteration. --video는 실측 14.4 s/iter로 2.06배 비용이라 학습 중에는 끄고 eval에서 렌더했다.

커리큘럼 압축 — 기본 스케줄은 2000–15500에 걸치고 VOC가 0이 되는 지점이 14000(이 머신에서 약 27 h). 4079/15500 = 0.2632를 곱해 timestep_schedule=[526,921,1316,1711,2105,2500,2895,3290,3684,4079]로 넘겼다. VOC 0.0 도달 3684, 자력 구간 395 iteration.

해석된 설정(params/env.yaml)으로 가중치와 스케줄이 의도대로 적용됐음을 확인했다.

3.1 영상 확인 — 정책은 박스를 들지 않는다

eval 영상(400 스텝, 물리 롤아웃)에서 정책은 박스를 들어올리지 않았다. 레퍼런스는 분명히 든다 — 물체 z 범위 15.4 cm, 전체 프레임의 49.5%가 바닥에서 2 cm 이상 떠 있고, 수평 이동은 3 cm뿐인 "들었다 놓는" 동작이다.

지표가 실패를 보이지 못한 이유는 두 가지이고, 둘 다 이 클립의 동작 폭에서 비롯된다.

지표보고된 값박스가 전혀 움직이지 않을 때의 값결론
object_away_from_trajectory 종료율4.2%임계값 0.20 m 대비 레퍼런스 최대 이탈 0.1555 m안 들어도 종료 불가. 완주율 95.8%는 무동작 정책도 받는 점수

3.2 실패 원인 — 예산이 잘못된 구간에 갔다

커리큘럼의 물체 추종 가중치 스케줄은 마지막 단계에서만 뛴다:

rewards_object_keypoints_tracking_exp: [0.0, 0.1, 0.25, 0.25, 0.5, 0.5, 1.0, 1.0, 1.0, 20.0]
virtual_object_control_scale_factor:   [1.0, 0.75, 0.5, 0.25, 0.1, 0.05, 0.025, 0.01, 0.0, 0.0]

학습 대부분에서 물체 추종 가중치는 ≤1.0, force_closure는 5.0이었다. 정책은 잡는 자세를 최적화할 동기는 강했지만 들 동기는 거의 없었고, 그동안 박스는 VOC가 들어주고 있었다. VOC가 0이 되고 추종 가중치가 20으로 뛰는 iteration 3684 이후 남은 것은 395 iteration이었다.

VOC = 0 시점이후 남은 iteration
기본 스케줄 (20000)140006000

비례 압축은 단계별 샘플을 1/4로 줄인다고 예고했지만, 결정적인 마지막 구간은 1/15로 줄었다. 자력으로 드는 법을 배우는 데 필요한 것은 비율이 아니라 절대 샘플 수였다. 손목 오차가 오른손 17.1 cm / 왼손 8.2 cm로 벌어진 것도 같은 맥락에서 재해석된다 — CHORD가 허용하는 "다른 파지 자세"가 아니라, 레퍼런스를 따르지도 물체를 들지도 못한 상태다.

7. 남은 문제와 다음 단계

7.1 코드 결함 (발견, 미수정)

  • scripts/rsl_rl/eval.py — viewer.env_index=6을 클램프하지 않아 --num_envs < 7이면 항상 실패. dummy_agent.py의 두 줄을 옮기면 된다. 이번엔 env.viewer.env_index=0으로 우회.
  • run_ego_wilor.py 결과 패키징 — result/가 존재하면 건너뛰어 정제 결과가 번들에 반영되지 않는다. 정제 플래그가 켜졌을 때는 재패키징해야 한다.
  • level_result_bundle.py — 축 평가와 적용이 같은 정규 탐색을 각각 수행(4 m × 2). 탐색 결과를 캐시하거나 --up_rank 비교를 내장하면 절반.
  • out/timing/rg_time.sh — 파이프라인 종료코드를 pipefail 없이 읽어 실패 1건을 complete로 기록.
  • object_away_from_trajectory 임계값 0.20 m — 동작 폭이 그보다 작은 클립에서는 종료 조건이 작동하지 않는다.

7.2 다음 실험을 위한 제안

  • 진단 지표부터. 학습 중 물체 z 높이(또는 레퍼런스 대비 들림 비율)를 직접 기록해야 한다. 지금은 8시간 뒤 영상으로만 실패를 알 수 있다.
  • 예산을 VOC=0 구간에 몰기. 비례 압축 대신 앞 단계를 줄이고 자력 구간을 길게(예: 4079 중 2000). 현재 395의 5배.
  • 물체 추종 가중치를 일찍 올리기. 마지막 20.0 점프를 앞당기거나 완만하게. 지금은 8시간 내내 잡기만 연습하고 들기는 47분 연습한 구조다.
  • 기본 스케줄 전체 실행(≈39 h)이 가능하면 압축 없이 비교 기준을 만든다.
  • 재구성 측 개선 여지: 손 추적을 DynHaMR로 바꾸고, gsplat의 w_hand_scale_prior를 낮춰 논문 서술대로 스케일이 공동 최적화되는지 확인.

모든 실행은 GPU 6/7로 제한했으며(--gpus device=6,7), 재구성 오케스트레이션은 ~/v2d_recon 가상환경, 그라운딩은 rg-retarget 컨테이너에서 수행했다. 본 문서의 수치는 out/train_8h.log, params/env.yaml, timing/stage_timing.json, 그리고 세션 중 실행한 검증 스크립트 출력에서 그대로 가져왔다.
